# Report 1 — Forge H2를 가장 쉽게 설명하면

## 한 문장

Forge H2는 수소발전소를 짓는 일을 **전문가 회사 전체의 업무 흐름으로 바꾸어 실행하는 프로젝트 운영체계**다.

일반적인 AI 채팅은 질문에 답한다. Forge H2는 질문을 받으면 다음 일을 연결한다.

```text
무엇을 만들지 정한다
→ 필요한 전문가를 부른다
→ 각 전문가가 근거를 찾아 의견을 낸다
→ 회의를 열어 서로 다른 의견을 듣는다
→ 사람이 결정하고 서명한다
→ 승인된 결과로 다음 일을 시작한다
```

## “딸깍”의 실제 의미

딸깍 한 번으로 발전소가 자동 건설되는 것은 아니다. 딸깍은 회사의 여러 부서가 해야 할 일을 자동으로 펼치고, 순서대로 실행하고, 막힌 곳을 알려주는 시작 버튼이다.

사용자가 다음과 같이 입력한다고 하자.

> 어느 지역에 100MW 수소발전소를 짓고 싶다. 연간 4,000시간 운전하고 수소는 배관으로 공급한다.

Forge H2는 자동으로 다음을 한다.

1. 부지 좌표·전력수요·수소공급·운전조건을 정리한다.
2. 사업성·부지·수소·전기·안전·환경·인허가 작업으로 나눈다.
3. 각 작업에 맞는 전문가 Agent를 호출한다.
4. 필요한 법규·표준·프로젝트 자료를 지식 데이터베이스에서 가져온다.
5. 전문가들의 의견이 같은지, 충돌하는지 확인한다.
6. 충돌하거나 위험하면 회의를 열고 반대의견도 기록한다.
7. Sponsor·Chief Engineer·HSE 등 실제 책임자의 결정을 요청한다.
8. 승인된 결과만 다음 단계의 입력으로 넘긴다.

## 누가 일하는가

### 1. 의사결정자 Agent

Sponsor, PMO, Chief Engineer, HSE, EPC Manager, Operations Manager 같은 회사의 책임자 역할이다.

이들은 “무엇을 할지”, “언제 멈출지”, “어떤 조건에서 다음 단계로 갈지”를 결정하도록 회의를 구성한다.

### 2. 기술전문가 Agent

수소공정, 압력설비, 기계, 배관, 전기, 계통, 계측제어, 토목, 구조, 소방, 공정안전, 환경, 시운전, 운영 등 전문분야를 담당한다.

대한민국 프로젝트에서는 기술사급 전문가를 실제 담당자로 배정할 수 있도록 자격·경험·업무범위를 확인한다. Agent 자체가 기술사가 되는 것은 아니다.

### 3. 재무·법무 자문 Agent

Project Finance, 회계·세무, PPA, EPC 계약, 토지, 인허가, 환경법, 보험, 클레임, 노무 자문을 담당한다.

자문 Agent는 선택지를 만들고 위험을 설명하지만, 계약서 서명이나 법률적 책임을 대신하지 않는다.

### 4. 국제 프로젝트 Agent

외국에서 발전소를 짓거나 해외 금융·EPC·공급사가 참여하면 International Program Director, Owner’s Engineer, Lender’s Technical Advisor, 현지 법정기술자, 인증기관, E&S 전문가, 통관·수출통제·환율 전문가를 추가한다.

## 지식 데이터베이스는 무엇인가

각 Agent가 매번 처음부터 검색하지 않도록 회사의 기본 지식을 저장해 둔 것이다.

구조는 두 겹이다. 중앙 Source Catalog가 원본 장부이고, 각 Agent에는 자기 전문분야에 맞춘 읽기 전용 JSON 전문지식 DB가 하나씩 있다. 모든 Agent는 자기 DB를 먼저 보고, 필요할 때 다른 Agent DB와 중앙 장부를 함께 조회할 수 있다. Agent DB에 직접 기록하지 않고 중앙 JSON 장부에 새 판본을 등록한 뒤 다시 만든다.

저장되는 내용은 다음과 같다.

- 법령·허가·KGS Code
- ISO·IEC·NFPA 등 국제표준의 적용 정보
- 수소·발전·안전·환경 설계기준
- 공급사 자료와 시험성적서
- EPC 계약·금융·보험 조건
- 과거 프로젝트와 운영 교훈
- 현재 프로젝트의 승인된 결정과 기준선

중요한 점은 지식만 저장하지 않는다는 것이다. 지식마다 다음 정보를 함께 저장한다.

```text
무엇인가
누가 발행했는가
어느 나라에 적용되는가
어느 판본인가
언제 확인했는가
누가 검토했는가
어떤 Agent와 단계에서 쓰는가
URL이 없으면 내부 문서 위치와 Evidence ID가 무엇인가
```

## Professional이란 무엇인가

Professional은 단순히 똑똑한 사람이나 AI가 아니다.

```text
검증된 자격
+ 관련 실무경험
+ 명확한 업무범위
+ 근거에 기반한 판단
+ 이해상충 공개
+ 독립적인 검토능력
+ 결과에 대한 책임과 서명
+ 최신 지식 재확인
```

이 조건을 만족한 실제 사람만 중요한 설계·안전·허가·시공·운영 결과를 승인할 수 있다. AI는 자료를 찾고 계산하고 초안을 만들 수 있지만, Professional의 법적 책임을 대체하지 않는다.

## 하나의 일이 진행되는 예

“수소 저장탱크를 얼마나 설치해야 하는가?”라는 질문이 들어오면:

1. Hydrogen Process Agent가 필요한 수소량을 계산한다.
2. Storage·Pressure Agent가 압력·저장·방출조건을 검토한다.
3. Process Safety Agent가 누출·화재·폭발 시나리오를 확인한다.
4. 지식 데이터베이스가 KGS·ISO·NFPA·공급사 근거를 불러온다.
5. 의견이 다르면 HSE 회의를 연다.
6. 회의 결과를 Decision으로 저장한다.
7. 실제 Chief Engineer와 HSE 책임자가 승인한다.
8. 승인된 저장 기준만 부지면적·배관·소방·조달 미션으로 전달한다.

## 결론

Forge H2는 “대답하는 AI”가 아니라 **전문가·자문단·조직·지식·회의·승인·문서를 하나로 묶는 건설 프로젝트 운영회사**다.

인터넷이 끊겨도 로컬 JSON 원장과 Agent DB, 출처 해시 번들을 사용해 계속 검토할 수 있다. 다만 표준·법규·계약 원문이 로컬에 없으면 해당 결과는 참고용으로만 남고, 설계 기준선으로 승격되지 않는다.

실제 기준 파일은 다음이다.

- Agent 목록: `agents/registry.json`
- 국제 Agent: `agents/international-overlay.json`
- 지식 저장소: `knowledge/registry.json`
- 중앙 JSON 원장: `knowledge/catalog.json`
- 지식 검색 실행기: `knowledge/pipeline.py`
- Professional 자격 계약: `schemas/professional-profile.schema.json`
