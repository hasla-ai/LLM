# Agent 결정회의 운영 프로토콜

## 1. 회의의 목적

회의는 Agent의 답변을 평균 내는 곳이 아니다. 각 전문영역의 근거와 반대 의견을 공개적으로 모으고, 누가 무엇을 책임지고 어떤 조건에서 다음 단계로 갈지 결정하는 통제 지점이다.

## 2. 회의가 자동으로 열리는 조건

다음 중 하나라도 해당하면 회의를 연다.

- 두 전문분야의 계산·가정·추천이 충돌한다.
- 미션 위험등급이 C 또는 D다.
- G0–G7 게이트를 판정한다.
- C3 이상 변경요청이다.
- 안전·법규·허가·계약·시공·운영 통제값을 기준선으로 승격한다.
- 필수 근거가 오래되었거나 서로 다른 버전이다.
- Agent가 `hold`, `stop`, `request_more_data`를 반환한다.

## 3. 회의 실행 순서

```text
1. PMO가 회의 ID·목적·결정 질문·기한을 만든다.
2. 의장이 필수 Agent와 인간 참석자를 지정한다.
3. 각 Agent가 독립적으로 근거와 입장을 제출한다.
4. 의장은 모든 입장을 읽고 찬성·반대·조건·미확인을 분리한다.
5. 충돌한 가정과 계산을 별도 이슈로 만든다.
6. 추가 자료가 필요하면 회의를 중단하고 미션을 BLOCKED로 돌린다.
7. 합의 가능한 선택지를 2개 이상 유지한다.
8. 의사결정권자가 선택하고 인간 서명자를 지정한다.
9. 결정·조건·담당자·기한·근거를 append-only로 기록한다.
10. 승인된 출력만 다음 미션 또는 게이트 입력으로 승격한다.
```

## 4. “귀를 열고 듣기” 규칙

- Agent의 원문 요약을 삭제하지 않고 `invocation_id`로 연결한다.
- 다수 의견이라고 해서 안전·법규·법무 이견을 묵살하지 않는다.
- 반대 의견에는 주장, 근거, 영향, 해소 조건을 반드시 기록한다.
- 회의 의장은 자신의 추천을 먼저 제시하지 않고 독립 의견 수집을 먼저 완료한다.
- 이견이 남아 있으면 `conditional`, `hold`, `stop` 중 하나로 결정한다.
- “문제 없음”은 근거와 검토범위가 함께 있을 때만 유효하다.

## 5. 회의 유형

| 유형 | 기본 의장 | 주 사용 시점 | 필수 결과 |
|---|---|---|---|
| `standup` | PMO | 일일 실행 | 차단·담당·기한 |
| `pmo_integration` | PMO/프로그램 디렉터 | 주간 통합 | 일정·비용·의존성·이슈 |
| `design_interface` | Chief Engineer | 분야 간 설계 | 인터페이스 결정·재실행 미션 |
| `hse_regulatory` | HSE/Regulatory | 안전·허가 | Safety Case·허가 차단 |
| `steering_committee` | Sponsor | 예산·범위·착공 | 투자·변경·중단 결정 |
| `independent_review` | Independent Reviewer | G3/G4/G6 | 독립 의견·보완목록 |
| `gate_review` | 해당 게이트 승인자 | G0–G7 | PASS/CONDITIONAL/HOLD/STOP |
| `change_review` | 변경등급별 승인자 | 변경요청 | 영향분석·재승인 범위 |

## 6. 회의가 끝나지 않는 조건

- 필수 인간 참석자가 없다.
- 안전·허가·계통·법무의 핵심 이견이 남아 있다.
- 근거 버전과 적용 관할을 확인할 수 없다.
- 추천 Agent와 승인 Agent의 독립성이 깨졌다.
- 결정에 필요한 입력이 `null`인데 대체 가정이 승인되지 않았다.

이때 회의 상태는 `blocked`이고, 다음 단계는 실행하지 않는다.
