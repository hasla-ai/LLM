# Forge H2 요구사항 기준선

문서 ID: FHZ-REQ-001  
버전: 0.1  
상태: 기준선 초안  
승인 필요: Sponsor, Product Owner, Chief Engineer, HSE/Regulatory Authority  
대상: Forge H2 소프트웨어와 이를 사용하는 수소발전소 프로젝트 조직

## 1. 제품 목적

Forge H2는 사용자의 사업 요구를 수소발전소 건설 프로젝트의 실행 가능한 미션 그래프로 변환하고, 각 미션의 입력·출력·근거·가정·검토자·승인상태를 추적하는 엔지니어링 프로젝트 운영 플랫폼이다.

제품은 다음을 제공해야 한다.

- 사업 요구사항에서 프로젝트 상태를 자동 생성한다.
- 수소·발전·계통·입지·안전·환경·인허가·EPC 흐름을 연결한다.
- 반복 계산은 결정론적 엔진으로 수행한다.
- AI가 문서·검토목록·질문·위험 후보를 생성한다.
- 사람이 검토하고 승인하지 않은 고위험 결과는 다음 기준선으로 승격하지 않는다.

## 2. 사용자와 권한

| 사용자 | 필요한 기능 | 금지 기능 |
|---|---|---|
| Sponsor | 대시보드·게이트·예산·중단 결정 | 전문 안전값 직접 승인 |
| PMO | WBS·일정·리스크·변경·회의·보고 | 설계 책임자 대체 |
| 전문 엔지니어 | 분야별 입력·계산·검토·승인 | 타 분야 승인 위조 |
| HSE/Regulatory | 법규·안전·허가 검토·차단 | 출처 없는 기준 승인 |
| EPC/시공 | 도면·구매·검사·현장 진행 | 승인 전 IFC 사용 |
| 운영팀 | 운전·정비·비상·인수 | 미검증 설계 변경 |
| AI/Data 관리자 | 모델·데이터·근거·평가 관리 | 기술·안전 승인 대행 |
| 외부 검토자 | 할당된 검토와 의견 기록 | 프로젝트 기준선 임의변경 |

## 3. 핵심 업무 흐름

```text
입력
 → ProjectIntent
 → Mission Graph
 → Evidence Collection
 → Deterministic Calculation / AI Draft
 → Human Review
 → Gate Decision
 → Baseline Update
 → Next Missions
```

## 4. 기능 요구사항

| ID | 우선순위 | 요구사항 | 수용기준 |
|---|---|---|---|
| FR-001 | P0 | 프로젝트를 생성하고 관할·사업주·목표·용량을 저장해야 한다. | 프로젝트 ID가 생성되고 변경 이력이 남는다. |
| FR-002 | P0 | 자연어 사업요구를 `ProjectIntent`로 정규화해야 한다. | 원문, 추출값, 불확실성, 누락값을 함께 보존한다. |
| FR-003 | P0 | 모든 미션은 버전이 있는 입력·출력 스키마를 가져야 한다. | 스키마 검증 실패 시 실행되지 않는다. |
| FR-004 | P0 | 미션 선행조건과 후속 미션을 그래프로 관리해야 한다. | 선행 미션 미완료 시 `BLOCKED`를 반환한다. |
| FR-005 | P0 | 미션 실행 결과에 상태·근거·가정·담당자·검토자를 기록해야 한다. | 결과만 저장되고 근거가 없는 실행은 실패한다. |
| FR-006 | P0 | 프로젝트·미션·문서·근거·결정·리스크를 연결해야 한다. | 모든 산출물에서 상위 프로젝트와 근거를 역추적할 수 있다. |
| FR-007 | P0 | `PASS`, `BLOCKED`, `HUMAN_REVIEW`, `FAIL` 상태를 지원해야 한다. | 상태 전이가 권한과 조건에 의해 제한된다. |
| FR-008 | P0 | G0–G7 게이트를 생성·검토·승인·보류할 수 있어야 한다. | 게이트마다 필수 입력과 승인자가 강제된다. |
| FR-009 | P0 | 게이트 미통과 결과의 IFC·시공·승인 문서 사용을 차단해야 한다. | 차단 이벤트와 승인 요청이 생성된다. |
| FR-010 | P0 | 프로젝트 변경의 비용·일정·안전·법규 영향을 계산해야 한다. | 변경이 영향을 받는 미션과 문서를 표시한다. |
| FR-011 | P0 | 좌표·필지·설비·공정 연결을 GIS 그래프로 저장해야 한다. | WGS84 좌표와 데이터 출처가 보존된다. |
| FR-012 | P0 | 수소량·저장량·발전량·면적·보조전력을 계산해야 한다. | 입력 단위와 계산 버전이 결과에 포함된다. |
| FR-013 | P0 | 전력계통 접속 후보와 사전협의 결과를 관리해야 한다. | 접속점·조건·문서·회신일이 연결된다. |
| FR-014 | P0 | 법규·기술기준·KGS 자료를 Evidence로 관리해야 한다. | 출처 URL·발행일·효력기간·원문 위치가 기록된다. |
| FR-015 | P0 | 안전성 검토 후보를 생성하되 최종 안전판정을 금지해야 한다. | 고위험 결과는 `HUMAN_REVIEW`로 고정된다. |
| FR-016 | P0 | 인허가 매트릭스를 관할·시설·조건별로 생성해야 한다. | 요구자료·담당기관·선행조건·상태가 표시된다. |
| FR-017 | P0 | 예비 설계문서와 검토목록을 생성해야 한다. | 문서에 입력·가정·근거·제한사항이 포함된다. |
| FR-018 | P0 | 문서 버전과 승인 상태를 관리해야 한다. | 승인 전 문서가 기준선 문서로 표시되지 않는다. |
| FR-019 | P1 | PFD·P&ID·SLD·설비목록에서 구조화 데이터를 추출해야 한다. | 추출 원문 위치와 추출 신뢰도가 저장된다. |
| FR-020 | P1 | 문서 간 압력·유량·재질·태그·용량 불일치를 탐지해야 한다. | 충돌 위치와 우선 검토자를 표시한다. |
| FR-021 | P1 | HAZID·HAZOP·LOPA 회의 준비자료를 생성해야 한다. | 노드·이탈·원인·결과·보호계층 후보가 포함된다. |
| FR-022 | P1 | 공급사·장비·성능보증·장기납기를 관리해야 한다. | 벤더 자료와 계약조건이 설비에 연결된다. |
| FR-023 | P1 | RFI·RFP·견적·기술평가·상업평가를 관리해야 한다. | 기술점수와 가격점수가 분리되어 기록된다. |
| FR-024 | P1 | 일정·임계경로·자원·지연영향을 관리해야 한다. | 변경 시 게이트와 완공일 영향이 표시된다. |
| FR-025 | P1 | 검사·시험·품질부적합·시정조치를 관리해야 한다. | 검사기록과 설비·도면·계약이 연결된다. |
| FR-026 | P1 | FAT·SAT·압력시험·루프체크·성능시험을 추적해야 한다. | 합격 조건과 미해결 항목이 명확하다. |
| FR-027 | P1 | 준공도서·운영매뉴얼·교육·인수인계를 관리해야 한다. | COD 조건과 인수 책임자가 기록된다. |
| FR-028 | P1 | 운영 데이터·정비·사고·MOC를 프로젝트 그래프에 연결해야 한다. | 운영 변경이 설계·허가·안전에 역추적된다. |
| FR-029 | P1 | 역할기반 접근제어와 승인권한을 제공해야 한다. | 역할 없는 사용자는 승인·기준선 변경을 할 수 없다. |
| FR-030 | P1 | 모든 API·문서·승인·다운로드를 감사로그에 기록해야 한다. | 누가 언제 무엇을 했는지 복구 가능하다. |
| FR-031 | P1 | 프로젝트 전체를 JSON·Markdown·PDF·CSV로 내보내야 한다. | 내보낸 파일에 버전·생성시각·프로젝트 ID가 포함된다. |
| FR-032 | P2 | 외부 GIS·기상·토지·규제·계통 데이터 커넥터를 제공해야 한다. | 갱신주기와 라이선스가 기록된다. |
| FR-033 | P2 | 과거 프로젝트와 전문가 검토를 평가 데이터로 수집해야 한다. | 비식별화·동의·데이터 계보가 확인된다. |
| FR-034 | P2 | 운영 데이터로 고장예측·운전추천을 제공해야 한다. | 추천과 자동제어가 분리되고 사람이 승인한다. |

## 6. 수용 테스트

제품 기준선은 다음을 모두 통과해야 한다.

- 신규 사용자가 한 번의 프로젝트 생성으로 G0 입력을 완료한다.
- 필수 입력이 없을 때 시스템이 추정값을 확정하지 않고 `BLOCKED`를 반환한다.
- 법규 근거가 없는 안전 답변이 기준선 문서로 승격되지 않는다.
- 계산기 버전과 입력값으로 결과를 재현할 수 있다.
- 승인권한이 없는 사용자가 게이트를 통과시킬 수 없다.
- 설계변경 한 건이 영향받는 문서·미션·승인을 모두 표시한다.
- 전문가가 AI 결과를 수정하면 수정 전후와 이유가 저장된다.
- 프로젝트 스냅샷을 백업하고 다른 환경에서 복구할 수 있다.

## 7. 기준선 변경 규칙

이 문서의 P0 요구사항 변경은 PMO, Product Owner, Chief Engineer, HSE/Regulatory Authority의 공동 검토가 필요하다. 안전·법규·권한 요구사항은 Sponsor 단독으로 완화할 수 없다.
