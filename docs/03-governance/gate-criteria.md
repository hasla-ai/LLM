# Forge H2 게이트 판정기준

문서 ID: FHZ-GATE-001  
목적: 프로젝트가 다음 단계로 넘어갈 수 있는 객관적 조건과 승인권한을 정의한다.

## 1. 판정값

- `PASS`: 모든 필수조건 통과
- `CONDITIONAL`: 제한된 조건과 기한을 명시하고 진행
- `HOLD`: 보완자료 대기, 기준선 승격 금지
- `STOP`: 사업·안전·법규·금융상 진행 불가
- `REOPEN`: 새로운 근거 또는 변경으로 이미 통과한 게이트 재검토

`CONDITIONAL`은 안전·법정 필수조건을 면제하는 수단이 아니다.

## 2. G0 — 프로젝트 헌장

### 진입조건

- 사업 목적과 고객이 존재한다.
- Sponsor와 Product Owner가 지정됐다.
- 대상 국가·지역과 초기 발전방식이 기록됐다.

### 통과조건

- ProjectIntent 승인
- 범위·제외범위·성공기준 승인
- PMO·Chief Engineer·HSE 책임자 지정
- 예산·초기 일정·의사결정 권한 확정
- 리스크 레지스터와 의사결정 로그 개설

### 차단조건

- 책임자 부재
- 사업 목적과 수요처 불명확
- 안전·법규 검토를 하지 않겠다는 요구

### 승인

Sponsor `A`, PMO `R`, Chief Engineer/HSE `C`

## 3. G1 — 사업성·입지 타당성

### 필수 입력

- 전력수요·판매처·운전시간
- 발전용량과 발전방식 후보
- 수소 공급 후보·가격·물량
- 부지 후보와 토지 통제권
- 계통 접속 후보
- CAPEX·OPEX·수익·금융 가정

### 통과조건

- 사업성 시나리오가 기준선화됨
- 부지 후보에 중대한 토지·용도·환경 배제조건이 없음
- 수소·발전·계통의 초기 실현가능성이 확인됨
- 탈락 후보와 사유가 기록됨
- 최악 시나리오에서의 중단기준이 승인됨

### 차단조건

- 수요처가 전혀 없음
- 부지 권리 또는 용도상 사용 불가
- 수소 공급량·가격이 목표를 충족하지 못함
- 계통 접속 가능성이 전혀 없음

### 승인

Sponsor `A`, PMO/Commercial/Chief Engineer `R`, HSE/Finance `C`

## 4. G2 — 수소·발전·계통 기준선

### 필수 입력

- 수소 압력·순도·유량·온도·저장조건
- 공급계약 또는 공급사 기술자료
- 발전기 성능곡선·보증조건
- 보조전력·냉각·용수 조건
- 계통 사전협의·접속점·전력품질 조건

### 통과조건

- 수소 수급과 발전기 요구조건이 일치함
- 저장·압축·감압 용량이 계산됨
- 성능보증 항목과 시험방법이 정의됨
- 계통연계 검토 입력과 미해결 조건이 기록됨
- 전력시장·PPA·판매경로가 선택됨

### 차단조건

- 수소 품질이 발전기 요구를 만족하지 못함
- 공급계약 또는 대체공급이 없음
- 계통 사전협의에서 접속 가능성이 확인되지 않음
- 발전기 성능·납기·보증을 확인할 수 없음

### 승인

Chief Engineer `A`, Hydrogen/Power/Grid Leads `R`, Commercial/HSE `C`

## 5. G3 — 개념설계·안전·환경·인허가

### 필수 입력

- Design Basis
- PFD·설비목록·배치도·단선결선도
- 법규·기술기준·KGS 적용성 매트릭스
- HAZID·HAZOP/LOPA 계획 또는 결과
- 누출·화재·폭발·대피 검토 범위
- 환경영향평가·개발행위·건축·소방·가스 인허가 경로

### 통과조건

- 개념설계 간 인터페이스 충돌이 해결됨
- 위험 시나리오와 보호계층의 검토가 완료됨
- 필요한 정밀해석과 현장조사의 범위가 확정됨
- 인허가별 제출자료·기관·선행조건·일정이 정의됨
- 독립 검토자의 의견이 기록됨

### 차단조건

- 고위험 안전결정에 근거 또는 검토자가 없음
- 적용 법규·KGS Code가 식별되지 않음
- 환경·주민수용성·토지 문제가 프로젝트를 막음
- 위험 저감조치가 설계에 반영되지 않음

### 승인

HSE/Regulatory Authority `A`, Chief Engineer/Discipline Leads `R`, Independent Reviewer `C`

## 6. G4 — FEED·투자·착공결정

### 필수 입력

- 승인된 개념설계·Safety Case·Permit Matrix
- FEED 범위·설계계산·장비사양
- EPC 전략·RFP·벤더 평가
- 비용 기준선·일정 기준선·예비비
- 금융조건·보험·성능보증·계약조건

### 통과조건

- FEED 패키지가 비용·일정·안전 가정을 공개함
- EPC 책임 경계와 인터페이스가 계약에 반영됨
- 장기납기 품목의 발주전략이 있음
- 허가·계통·수소공급의 남은 조건과 책임자가 있음
- 투자수익·민감도·중단기준이 Sponsor에게 보고됨

### 차단조건

- 필수 허가 경로가 불명확
- 수소·계통·장비의 주요 계약이 없음
- 금융·보험·성능보증이 성립하지 않음
- 공정·비용 기준선이 신뢰할 수 없음

### 승인

Investment Committee `A`, Sponsor/Finance/Commercial `R`, Chief Engineer/HSE `C`

## 7. G5 — IFC·조달·시공준비

### 필수 입력

- IFC 도면·계산서·설비목록
- 허가조건 추적표
- 구매사양·벤더도면·검사계획
- 시공계획·품질계획·HSE Plan
- 현장 준비·물류·양중계획

### 통과조건

- IFC 도면의 승인상태가 명확함
- 변경사항이 모두 MOC로 처리됨
- 장비·배관·전기·계측의 검사기준이 준비됨
- 작업허가·격리·비상대응이 정의됨
- 시공·QA/QC·시운전 책임자가 지정됨

### 차단조건

- 승인 전 도면으로 시공하려는 경우
- 허가조건과 IFC가 불일치
- 위험작업의 작업허가·격리·비상절차 부재
- 장기납기 때문에 임계경로가 붕괴

### 승인

Chief Engineer `A`, EPC Manager/QA/Construction `R`, HSE/Regulatory `C`

## 8. G6 — 시운전·성능·안전검증

### 필수 입력

- 설치·검사·품질도서
- 세척·압력시험·전기시험·루프체크
- 시운전 절차와 비상절차
- 수소 투입 전 안전조건
- 계통 병입 조건

### 통과조건

- 미해결 품질부적합이 허용기준 이내
- ESD·가스검지·화재·인터록 시험 완료
- 수소 투입 전 체크리스트 승인
- 출력·효율·배출·소음·계통시험 결과 합격
- 예외와 잔여위험의 운영 인계가 승인됨

### 차단조건

- 안전계장 또는 비상정지 시험 실패
- 압력·누출·전기·보호계전 시험 실패
- 성능보증 미달 원인 미확정
- 준공·사용전검사·계통조건 미완료

### 승인

Commissioning Manager `A`, QA/Chief Engineer/Operations `R`, HSE `C`

## 9. G7 — 상업운전·운영 인수

### 필수 입력

- 성능시험·안전시험 결과
- 준공도서·As-built·운영매뉴얼
- 교육·자격·정비계획
- 허가·검사·계통·시장 등록자료
- 자산 태그·센서·데이터 품질

### 통과조건

- 운영팀이 자산과 절차를 인수함
- 법정검사·계통·시장·보험 조건이 확인됨
- 비상대응·정비·작업허가 체계가 운영 가능함
- 데이터·알람·감사로그가 정상임
- 성능보증·하자·잔여조치 책임자가 지정됨

### 차단조건

- 운영팀이 인수하지 않음
- 안전·허가·검사 조건 미완료
- 성능시험이 계약조건 미달
- 비상대응 또는 데이터 체계 부재

### 승인

Sponsor `A`, Operations/Commissioning/QA `R`, HSE/Regulatory/Chief Engineer `C`

## 10. 게이트 회의 운영

게이트 회의 자료는 최소 5영업일 전에 배포한다.

1. 기준선과 변경사항
2. 필수 미션 결과
3. Evidence 상태와 충돌
4. 미해결 리스크·이슈·가정
5. 비용·일정·임계경로
6. 안전·법규·환경 차단조건
7. 승인·보류·중단 선택지
8. 결정사항·담당자·기한

게이트 결과는 회의 종료 후 24시간 이내 Decision Log에 기록한다.

## 11. 면제와 재개방

- 법정 안전·인허가 조건은 면제할 수 없다.
- 조건부 통과는 보완항목·담당자·기한·재검토 게이트를 명시한다.
- 새로운 법규·설계변경·사고·공급조건 변경은 이전 게이트를 `REOPEN`할 수 있다.
- 게이트 재개방 시 영향을 받는 문서와 미션은 자동으로 `CHANGE_IMPACT_REQUIRED`가 된다.
